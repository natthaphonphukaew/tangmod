# ปรับคำตอบของทางมด

อ่าน [CLAUDE.md](../../../CLAUDE.md) ส่วน "ข้อมูล" ก่อน กติกาสำคัญที่สุดคือ **ห้ามแต่งข้อมูล**

รับคำถามจากผู้ใช้หนึ่งข้อหรือหลายข้อ (ถ้าผู้ใช้ให้ไฟล์จาก `npm run feedback` ให้อ่าน `.data/feedback-export.ndjson` — แถวที่ reason เป็น `auto_low_confidence` คือคำถามที่มดตอบเองว่าข้อมูลไม่พอ ส่วนที่เหลือผู้ใช้กด "ตอบไม่ตรง") แล้วทำทีละข้อตามนี้

## 1. ตรวจว่าอยู่บน branch ไม่ใช่ main
`git branch --show-current` ถ้าเป็น `main` ให้สร้าง branch `data/<หัวข้อ>` ก่อน (ดึง main ล่าสุดก่อน)

## 2. ดูอาการ
- `npm run eval -- --only=<id>` ถ้าข้อนี้มีใน eval แล้ว หรือถามผู้ใช้ว่าแอปตอบว่าอะไร
- `npm run retrieve -- "<คำถาม>"` (ไม่ใช้โควตา) ดูว่าระบบส่งข้อมูลชิ้นไหนให้ AI

## 3. แยกสาเหตุ แล้วแก้ให้ตรงจุด
- **ไม่มีชิ้นไหนมีคำตอบ → ขาดข้อมูล**
  - ค้นหาแหล่งที่เชื่อถือได้ (เว็บมหาวิทยาลัย/คณะก่อน แล้วค่อยเพจนักศึกษา รีวิว) เปิดหน้านั้นอ่านจริง จดลิงก์
  - หาไม่ได้ หรือเป็นเรื่องที่ต้องไปถาม/ไปดูเอง (ราคาร้าน เวลาเปิด ความเห็นรุ่นพี่) → **อย่าเดา** บอกผู้ใช้ว่าต้องเก็บอะไร แล้วจดใน `content/DATA_STATUS.md` ส่วน "สิ่งที่ผู้พัฒนาต้องไปเก็บเอง"
  - ได้ข้อมูลแล้ว: เพิ่ม `## หัวข้อ` ในไฟล์ KB ที่เป็นเรื่องเดียวกัน หรือสร้างไฟล์ใหม่ `content/kb/<namespace>/<ชื่อ>.md` (frontmatter ครบ, tier ตรงกับแหล่ง)
  - ตัวเลขทางการที่มีโครงสร้างอยู่แล้ว (ค่าเทอม หลักสูตร วันรับสมัคร สถานที่) แก้ใน JSON (`content/programs/`, `content/admission/`, `content/places.json`) ไม่ใช่เขียนซ้ำใน KB
- **มีชิ้นที่ถูกแต่ไม่ติดรายการ → ค้นไม่เจอ**
  - ระบบค้นด้วยคำ (BM25 ตัดคำภาษาไทย) ดูบรรทัด "คำค้น" แล้วเติมคำที่คนใช้ถามลงในหัวข้อหรือเนื้อหาของชิ้นนั้น
  - ถ้าเป็นชื่อเล่นของตึก/สาขา เพิ่มใน `aliases` ของ `content/places.json` หรือ `content/programs/*.json` (ระบบจะดึงชิ้นนั้นมาเสมอเมื่อเจอชื่อ)
  - ไม่ต้องแก้ `lib/ai/retrieve.ts` ถ้าแก้ที่ข้อมูลได้
- **ชิ้นถูกอยู่ในรายการแล้วแต่ตอบผิด → กฎคำตอบ**
  - ดูกฎใน `lib/ai/prompt.ts` แก้ให้น้อยที่สุดและเป็นกฎทั่วไป ไม่ใช่กฎเฉพาะคำถามนี้
  - ต้องรัน `npm run eval` ทั้งชุดหลังแก้ ข้อเดิมที่เคยผ่านต้องไม่ตก

## 4. เพิ่มคำถาม eval
- ใส่ใน `eval/questions/<หัวข้อ>.json` (เรื่องใหม่ = ไฟล์ใหม่ เพื่อไม่ชนกับอีกคน) id ไม่ซ้ำ
- `include` ตรวจตัวเลข/คำที่ต้องมีในคำตอบ (regex) · คำถามที่ไม่มีข้อมูลจริงให้ใช้ `"cat": "unknown"` + `"admits_unknown": true` เพื่อกันไม่ให้ AI แต่งคำตอบ
- ถามแบบที่คนพิมพ์จริง ภาษาพูด สะกดไม่เป๊ะ ได้ยิ่งดี และถ้าเป็นไปได้ใส่ 2–3 แบบที่ถามเรื่องเดียวกัน

## 5. ตรวจ
- `npm test` ผ่าน
- `npm run eval -- --file=<หัวข้อ>` ผ่าน
- ถ้าแตะ `lib/ai/` รัน `npm run eval` ทั้งชุด

## 6. รายงานผู้ใช้
สรุปสั้น ๆ ต่อข้อ: สาเหตุ, แก้ที่ไฟล์ไหน, แหล่งข้อมูล (ลิงก์), ผล eval ก่อน/หลัง และสิ่งที่ยังต้องไปเก็บเอง · commit/push เมื่อผู้ใช้สั่ง แล้วเปิด PR ตามแบบฟอร์ม
