**ความยินยอม (สำคัญ ผู้เข้าร่วมส่วนใหญ่ยังไม่บรรลุนิติภาวะ)**
- ขออนุญาตครูหรือผู้ปกครองก่อน บอกว่าทดสอบเว็บของโปรเจกต์วิชาเรียน ใช้เวลาราว 30 นาที ไม่เก็บชื่อจริง
- ไม่ถ่ายใบหน้า ถ้าจะอัดหน้าจอให้ขออนุญาตก่อนทุกครั้ง และอัดเฉพาะหน้าจอ

- บอกผู้เข้าร่วมว่าไม่ต้องพิมพ์ชื่อ เบอร์ หรือโรงเรียนลงในแชท

## 1. สคริปต์ผู้คุม (อ่านออกเสียง)

> "ขอบคุณที่มาช่วยนะ วันนี้เราทดสอบ**เว็บ** ไม่ได้ทดสอบน้อง ถ้าทำไม่ได้หรือหาไม่เจอ แปลว่าเว็บออกแบบไม่ดี ไม่ใช่น้องผิด
>
> พี่จะให้ทำงานสั้น ๆ ทีละข้อ ระหว่างทำ อยากให้พูดสิ่งที่คิดออกมาดัง ๆ เช่น 'กำลังหาปุ่มนี้' 'งงตรงนี้' 'ไม่เชื่อตัวเลขนี้' จะช่วยพี่มาก
>
> พี่จะไม่ช่วยระหว่างทำ เพราะอยากเห็นว่าถ้าไม่มีใครช่วยจะเป็นยังไง ถ้าทำไม่ได้จริง ๆ บอกว่า 'ยอม' ได้เลย ไม่เป็นไร
>
> อย่าพิมพ์ชื่อจริง เบอร์ หรือชื่อโรงเรียนลงในแชทนะ"

**ระหว่างทดสอบ**
- อย่าบอกคำที่ต้องพิมพ์ อ่านคำสั่งตามที่เขียนไว้เท่านั้น
- ถ้าผู้เข้าร่วมเงียบนาน ให้ถามแค่ "ตอนนี้กำลังคิดอะไรอยู่"
- ถ้าถามว่า "ถูกไหม" ให้ตอบว่า "น้องคิดว่ายังไง" แล้วค่อยเฉลยตอนจบ
- ถ้าเว็บตอบผิด ให้จดคำถามและคำตอบไว้ แล้วให้ผู้เข้าร่วมลองกด "ตอบไม่ตรง" (เป็นการทดสอบปุ่มนั้นไปด้วย)

## 3. ส่วน A: เทียบกับการหาเองจากเว็บมหาวิทยาลัย (10 นาที)

ทำ 2 งาน แต่ละงานทำ 2 แบบ: **หาเอง** (เริ่มจาก Google หรือเว็บ มจธ. ได้ตามสะดวก) และ**ถามทางมด**

**สลับลำดับเพื่อความยุติธรรม** (คนที่ทำแบบที่สองจะรู้คำตอบอยู่แล้วบางส่วน):

| ผู้เข้าร่วม | งาน A1 | งาน A2 |
|---|---|---|
| P1, P3, P5 | หาเองก่อน → ทางมด | ทางมดก่อน → หาเอง |
| P2, P4 | ทางมดก่อน → หาเอง | หาเองก่อน → ทางมด |

จับเวลาตั้งแต่อ่านคำสั่งจบจนผู้เข้าร่วมพูดคำตอบ **จำกัดงานละ 5 นาที** เกินแล้วนับว่าไม่สำเร็จ

### A1 · ค่าเทอม
**อ่านให้ฟัง:** "ถ้าจะเรียนวิทยาการคอมพิวเตอร์ (CS) ที่คณะไอที มจธ. จนจบ ต้องใช้ค่าเทอมรวมประมาณเท่าไร"

**เฉลย:** ประมาณ **456,000 บาท** (เหมาจ่ายเทอมละ 57,000 × 8 เทอม) ที่มา: https://www.kmutt.ac.th/education/tuition-fees/
**สำเร็จ:** ตอบได้ 456,000 หรือบอกได้ว่าเทอมละ 57,000 × 8 เทอม

### A2 · รอบสมัคร
**อ่านให้ฟัง:** "ถ้าจะยื่นพอร์ตเข้าคณะไอที มจธ. รอบที่เปิดอยู่ตอนนี้ ต้องสมัครภายในวันไหน"

**เฉลย:** Active Recruitment รอบ 2 ของ SIT ปิด **25 พ.ย. 2569** (เปิด 27 ต.ค.) ที่มา: https://www.sit.kmutt.ac.th/active-recruitment-it/
**หมายเหตุ:** Eduzones ระบุ 20 ต.ค.–16 พ.ย. ซึ่งไม่ตรงกับเว็บ SIT ถ้าผู้เข้าร่วมตอบตามแหล่งนั้น ให้จดไว้ เป็นตัวอย่างที่ดีว่าข้อมูลข้างนอกขัดกันเอง
**สำเร็จ:** ตอบ 25 พ.ย. 2569

หลังแต่ละแบบ ถาม **SEQ:** "งานนี้ยากหรือง่ายแค่ไหน ให้คะแนน 1–7 (1 = ยากมาก, 7 = ง่ายมาก)"

## 6. แบบสอบถามหลังทดสอบ (5 นาที · ให้ผู้เข้าร่วมกรอกเอง)

### 6.1 ความง่ายในการใช้งาน (SUS)
ให้คะแนน 1–5 (1 = ไม่เห็นด้วยอย่างยิ่ง, 5 = เห็นด้วยอย่างยิ่ง)

| # | ข้อความ | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|---|
| 1 | ถ้ามีเรื่องอยากรู้เกี่ยวกับ มจธ. คิดว่าจะกลับมาใช้ทางมดบ่อย ๆ | | | | | |
| 2 | ทางมดซับซ้อนเกินความจำเป็น | | | | | |
| 3 | ทางมดใช้งานง่าย | | | | | |
| 4 | ต้องมีคนช่วยสอนถึงจะใช้ทางมดได้ | | | | | |
| 5 | ส่วนต่าง ๆ ของทางมด (แชท แผนที่ การ์ด เข็มทิศ) ทำงานเข้ากันดี | | | | | |
| 6 | มีหลายอย่างในทางมดที่ไม่สอดคล้องกัน ดูขัดกันเอง | | | | | |
| 7 | คิดว่าคนส่วนใหญ่จะเรียนรู้วิธีใช้ทางมดได้เร็ว | | | | | |
| 8 | ทางมดใช้งานยุ่งยาก | | | | | |
| 9 | มั่นใจตอนใช้ทางมด | | | | | |
| 10 | ต้องเรียนรู้หลายอย่างก่อนจะใช้ทางมดได้ | | | | | |

**วิธีคิดคะแนน (ผู้คุมทำ):** ข้อคี่ (1, 3, 5, 7, 9) = คะแนน − 1 · ข้อคู่ (2, 4, 6, 8, 10) = 5 − คะแนน · รวม 10 ข้อแล้ว × 2.5 ได้คะแนน 0–100 (ค่ากลางทั่วไปอยู่ที่ราว 68)
*SUS: System Usability Scale (John Brooke, 1986) ใช้ได้ฟรี ข้อความข้างบนแปลเป็นภาษาไทยโดยทีมทางมด*

### 6.2 ความน่าเชื่อถือ (1–5)
- เชื่อตัวเลขค่าเทอมและวันรับสมัครในทางมด ________
- ป้าย "ทางการ / ไม่เป็นทางการ / ข้อมูลตัวอย่าง" ช่วยให้รู้ว่าควรเชื่อแค่ไหน ________

### 6.3 คำถามปลายเปิด
1. ชอบอะไรที่สุด
2. หงุดหงิดหรืองงตรงไหนที่สุด
3. ถ้าแก้ได้ 1 อย่าง จะแก้อะไร
4. จะแนะนำทางมดให้เพื่อนที่กำลังเลือกมหาวิทยาลัยไหม เพราะอะไร

## 7. สรุปผล (ผู้คุมทำหลังทดสอบครบ)

| ตัวชี้วัด | วิธีคิด | เป้า |
|---|---|---|
| อัตราสำเร็จส่วน B | งานที่ "สำเร็จ" ÷ งานทั้งหมด | ≥ 80% |
| เวลาเทียบกับหาเอง (A1, A2) | ค่ามัธยฐานของเวลา ทางมด vs หาเอง | ทางมดเร็วกว่า |
| ความง่าย (SEQ) | ค่าเฉลี่ยแต่ละงาน | ≥ 5.5 · งานไหนต่ำกว่า 5 = ต้องแก้ |
| SUS | ค่าเฉลี่ยของทุกคน | ≥ 68 |
| คำตอบผิดของทางมด | นับจากใบจดผล | ทุกข้อเพิ่มเข้า `eval/questions/` |

**หลังสรุป**
1. ปัญหาที่เจอ ≥ 2 คน = แก้ก่อน ปัญหาที่เจอคนเดียว = จดไว้พิจารณา
2. คำตอบผิดทุกข้อ: เติมข้อมูลใน `content/` หรือแก้ prompt แล้วเพิ่มเป็นข้อสอบใน `eval/questions/` แล้วรัน `npm run eval`
3. ดึงข้อมูล "ตอบไม่ตรง" ที่ผู้เข้าร่วมกดไว้ด้วย `npm run feedback` (ตั้ง `DATABASE_URL` ของ Neon ก่อน)
4. จดผลสรุปลงสเปกหัวข้อ 11 พร้อมวันที่
